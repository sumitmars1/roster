# 抽签后秩序册赛程更新（Post-Draw Schedule Update）

当用户提交**抽签结果表**（Excel / Word / PDF / 图片）和一份**已生成的秩序册**（项目中已出册的 `.docx`，或直接上传的 `.docx`），按本流程执行更新，**可作为独立工作流触发**。

## 核心原则

1. **先读全抽签结果，再定位目标秩序册上下文**：
   - 必须完整读取抽签结果文件中的全部组别、小组编号（如 `A组`、`B组`、`部门A组`、`街镇A组`）、签位序号（如 `1、2、3...` 或 `A1、A2、B1...`）和真实队伍名称。
   - 若多个大组（如“部门男子组”和“街镇男子组”）同时存在 `A1/A2`，必须保留组别上下文映射，避免串组错替。
2. **上下文区分“抽签签位”与“阶段/名次/胜负关系”**：
   - **必须替换**：赛程表/对阵表中的抽签签位占位（例如 `A1 VS A2`、`A1—A2`、`部门A1 vs 部门A2`、`1—2` 配上组别列 `A组`，或小组抽签占位格子），以及分组表中需要填充的签位槽位。
   - **禁止误改（原样保留）**：
     - 场序胜负引用：`68胜——69胜`、`70负——71负`、`第5场胜者—第6场胜者` 等。
     - 小组出线后的排名引用：当赛别/轮次/语境为交叉赛、半决赛、决赛或排位赛时，`A组第一名 VS B组第二名` 或明确指代出线名次的 `A1 VS B2（出线对阵）` 不得被误替换成 1 号签/2 号签队伍。
3. **保留原稿 Word 版式并同步导出双格式**：
   - 对目标 `.docx` 采用就地 Run 级 XML 替换，保留字体、字号、对齐、颜色、加粗、表格边框、图片、页面设置和页眉页脚。
   - 替换完成后更新目录/书签页码并重新导出 PDF，返回完整变更核对清单（已替换场次 + 未受影响的胜负/排名引用 + 更新后的 `.docx` 与 `.pdf`）。

## 执行接口（代码 / MCP / CLI）

- 后端 runner：`draw_update.run_draw_update(target_docx, draw_source_paths, out_docx, out_pdf, ...)`
- 确定性 XML 替换核引擎：`draw_update.apply_draw_patches(target_docx, patches, out_docx, out_pdf)`
- 若通过接口触发：`POST /api/projects/{project_id}/draw-update` 或 `POST /api/draw-update`
